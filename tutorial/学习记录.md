### Node 测试入口需要指向测试文件

- 现象：第一次把测试脚本写成 `node --test dist/test` 时，构建成功，但 Node 报
  `Cannot find module '.../dist/test'`。
- 原因：当前 Node 测试运行器把这个参数当作一个模块路径，不会自动把目录展开
  成其中的测试文件。
- 解决方式：脚本改为 `node --test dist/test/*.test.js`，显式匹配编译后的测试文件。
- 真正学到的东西：构建成功只证明 TypeScript 能编译；测试发现规则也属于测试
  配置，必须实际运行才能验证。这个问题来自工程脚本，不是业务函数失败。

### 旧版 Git 初始化主分支

- 现象：`git init -b main` 报 `unknown switch 'b'`，且当时没有创建仓库。
- 原因：当前环境的 Git 版本不支持 `git init` 的 `-b` 参数。
- 解决方式：先执行 `git init`，再用 `git symbolic-ref HEAD refs/heads/main` 指定
  尚无提交时的主分支名称。
- 真正学到的东西：命令参数会随工具版本变化；失败后先确认是否产生了部分状态，
  再选择兼容写法，不能假定现代命令在所有环境都可用。

### VS Code 标红 `process` 和 `node:url`

- 现象：编辑器把 Node 全局变量 `process` 和内置模块 `node:url` 标红，看起来像
  没有发现依赖。
- 核验：本地 `node_modules/@types/node` 已安装，`pnpm exec tsc --noEmit` 零错误。
- 判断：项目依赖和 TypeScript 配置是有效的；问题位于 VS Code 当前打开的工作区、
  TypeScript 语言服务缓存或编辑器选择的 TypeScript 版本，不是业务代码错误。
- 排查顺序：确认打开项目根目录 → 执行 `pnpm install` → 选择工作区 TypeScript
  版本 → 重启 TypeScript Server → 必要时重新加载 VS Code 窗口。
- 实际解决：选择 `Use Workspace Version` 后红线消失。它让 VS Code 改用项目
  安装的 TypeScript，并用当前 `tsconfig.json` 和 `@types/node` 重建类型分析。
