# 第三方依赖与引入顺序

## 原项目依赖分组

| 依赖/技术 | 原项目位置 | 解决的问题 | 教学处理 |
|---|---|---|---|
| Node.js 22 + TypeScript | 宿主 `package.json` | 运行时与类型检查 | 第 1 课保留，先只用标准库 |
| pnpm | 根工程 | 工作区与可重复安装 | 第 1 课保留最小命令，不复制完整 workspace |
| better-sqlite3 / SQLite | `src/db`、mailbox | 中心实体与会话邮箱持久化 | 第 8/9 课使用 Node 内置 SQLite，减少安装复杂度 |
| Claude Agent SDK | `container/agent-runner` | 真正调用 Claude Code Agent | 第11课先用官方Anthropic文本SDK满足生成需求，暂不引入工具执行 |
| Bun | agent-runner 容器 | 容器内运行 runner 和 MCP | 教学第 10 课使用 Node，与宿主/测试保持同一运行时 |
| Docker | `container-runner`、Dockerfile | OS 级隔离和挂载 | 第 10 课需求驱动引入 |
| MCP SDK | `container/agent-runner/src/mcp-tools` | Agent 调用发送、调度、审批等工具 | 第 11/13 课按具体工具引入 |
| Chat SDK / 渠道 SDK | `src/channels` 与技能分支 | Slack、Discord 等平台连接 | 第 7 课先用本地渠道理解边界，后续只选一个示例 |
| cron-parser | scheduling | 周期任务的下一次时间 | 第 13 课引入 |
| OneCLI | gateway/provider | 凭据在请求时注入，不进入容器环境 | 第 15 课作为安全治理案例，可选简化 |
| YAML/kleur/clack | 配置/CLI/设置 | 人机交互和设置体验 | 教学项目只在最后按需要选取 |

## 引入原则

引入任何依赖时，教案必须回答：以前怎么做、旧方案出现什么具体问题、组件
解决什么、组件位于哪一层、本课只学习它哪些能力。不能因为原项目最终使用了
某库，就把它提前装进第 1 课。

## 第 10 课实际落地

- Docker 是运行工具，不是 npm 依赖。宿主先编译 TypeScript，再把处理器的
  三份 JS 与 ESM 声明复制到 Node 22 镜像，不复制私人数据库或宿主模块。
- `--process-container` 用 Docker 实际隔离运行；默认普通测试替换启动工具，
  `pnpm test:container` 则验证真实容器挂载，二者证明的范围不同。
- 当前只运行一轮，短生命周期不引入心跳；处理器无需联网，暂用
  `--network none`。下一课模型请求需要联网时再修改这个真实配置。

## 第 11 课实际落地

用 `@anthropic-ai/sdk@0.131.0` 调用Messages API。当前需求是完整文本回复，
因此暂不引入原项目的Agent工具循环、流式投递、MCP与注册中心。保持本地规则
作为实际可用的确定性实现，统一的是一个异步函数类型。普通SDK测试在回环
HTTP服务上验证真实请求，Docker测试仍用本地Provider，不等同于云端推理验收。
